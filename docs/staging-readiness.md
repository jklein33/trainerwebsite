# ステージング移行の確認表

## 接続先の制約（2026-09-19更新）

ステージング・本番はクライアント所有の `DawgStrength_dev` を使う。これまで接続・検証した専用Supabaseは開発者所有のため、ローカル検証専用でありVercelのステージング・本番には設定しない。

既存プロジェクトには別アプリ由来のテーブルがある。ユーザー提供の監査結果でAuthユーザー0人、Authトリガー・Storageバケット・Storageポリシーなしを確認済み。既存アプリが未使用とは断定しない。従来の `public` 向け初期SQLをそのまま適用せず、[クライアント環境の導入手順](client-staging-setup.md)を使う。

`course_staging` スキーマと `course-staging-media` バケットに対応するSQL・アプリ・型・テストを実装済み。ユーザーがクライアント環境へSQLを適用し、検証SQLの14項目すべてがtrueの結果を共有済み。その後 `.env.local` をステージング接続に変更し、Data APIの疎通・デモ教材投入・署名付き動画取得・ローカルの登録画面表示を確認済み。会員はまだ0人で、実会員の登録・メール・ログイン後の画面とVercel接続は未確認。スキーマを分けてもAuthユーザー・メール設定・Storageのポリシーはプロジェクト共通。将来Storageポリシーを追加する場合も、バケットを限定して他環境へ影響させない。

同じプロジェクト内でステージングと本番を同時稼働させる場合は、本番用のスキーマとバケットへの対応が追加で必要。Authの完全な独立は得られない。ステージング初期SQLでは既存Authユーザーを自動取り込みしない。

機能の確認日：2026-09-18。2026-09-19にクライアントDB向けのスキーマ対応を実装し、SQL適用・Data API疎通・デモ投入まで確認済み。ユーザーから必要な権限の取得とAuthのSite URL・Redirect URLs設定完了の報告あり。次は実会員の登録・ログインとVercelの接続確認。実販売への切り替えは別の受け入れ確認が必要。

今回の検証：`npm run build`（TypeScriptチェックを含む）、`npm run lint`、`npm test`（22件）が成功。今回ブラウザE2E一式は再実行していない。実Supabaseでの動画アップロード・再生確認は前日の記録を参照。

## ステージングを作る順番

1. 現在の未コミット差分をレビューし、コミットする。`.env.local` と `client-notes/` は引き続きGit対象外。
2. 現在の作業ブランチは `staging`。対象Vercelプロジェクトと本番ブランチを確認し、`staging` のPreviewデプロイを使う。新規プロジェクトは初回デプロイがProduction扱いになるため、本番サイトのドメインを割り当てず、検証用の接続情報だけを設定する。
3. 上記の既存プロジェクト調査・スキーマ対応後、対象環境にクライアント所有SupabaseのURL・公開キー・サーバー用キーを設定する。開発者所有の `.env.local` の接続先をそのままコピーしない。単一ホストの検証なら `NEXT_PUBLIC_SITE_URL` / `NEXT_PUBLIC_COURSE_URL` は省略可能。
4. 安定した検証URL（ブランチURL等）を決め、Supabase AuthのSite URLとRedirect URLsに反映する。ローカルのコールバック許可も残す。登録・メール確認は同じブラウザで行う。
5. Stripeを試すときはテスト用商品・買い切りPriceをコースに紐付け、テストキーと、その検証URLの `/api/stripe/webhook` 専用署名シークレットを設定する。環境変数の変更後は再デプロイする。
6. Vercel Deployment Protectionが有効なら、レビュー担当者・認証コールバック・Stripe Webhookが到達できる構成を確認する。Webhookには必要に応じて公式のProtection Bypass for Automationを使い、アプリ側のStripe署名検証も維持する。秘密値をGitや共有資料へ書かない。
7. 実アプリの `/learn` と `/admin` で検証する。`/preview` は開発モード専用なのでVercelでは404になる。

## ステージング上で残す受け入れ確認

- 一般会員による登録・確認・ログイン・ログアウト・パスワード再設定。Custom SMTPと送信元の設定を確認し、クライアントのメールアドレスにも送信できるようにする。問い合わせフォーム用Resend変数とは別設定。
- 一般会員によるテスト購入 → 自動権限付与 → 再ログイン後の閲覧。Webhook再送・失敗復旧、全額返金・一部返金・異議申し立て。
- 未購入・別コース購入・停止会員のDB/API/Storageへのアクセス拒否。現在の運営アカウントは管理者なので、未購入状態の検証には別の通常会員を使う。
- 実際の長いMP4でアップロード、中断・再開、再読み込み後の再開、差し替え・削除、長時間再生。Supabaseの全体ファイル上限・容量・転送量を確認する。
- iPhone/iPad/Android実機のレイアウト、動画、PWAインストール、通信断、ログアウト後の表示。
