# 開発用コースデータ

`scripts/seed-course-demo.mjs` で開発・ステージングSupabaseに画面確認用データを追加できます。本番では実行しないでください。

```powershell
node scripts/seed-course-demo.mjs --project-ref <開発プロジェクトのID> --learner-id <確認済み会員のUUID> --apply
```

まだ会員がいない環境では、教材のみを投入できます。

```powershell
node scripts/seed-course-demo.mjs --project-ref <ステージングプロジェクトのID> --content-only --apply
```

接続情報はGit管理対象外の `.env.local` から読み込みます。指定したプロジェクトと接続先の一致を確認します。`--learner-id` を指定する場合は対象会員のメールが確認済みである必要があります。会員のロールは変更せず、指定会員にデモ2コースの閲覧権限を追加します。`--content-only` では会員・閲覧権限を作成しません。固定UUIDを使い、既存レコードは上書きせずに不足分だけ追加します。途中失敗した場合は同じ引数で再実行できます。DBとStorageをまたぐため、全体が単一トランザクションになるわけではありません。

## 追加するデータ

- コース4件：Strength Foundations、Nutrition & Recovery、Hypertrophy Essentials、Coach Workshop。タイトルに `Demo`、概要に `DEVELOPMENT DEMO` を表示します。
- 公開コース3件、下書きコース1件。
- モジュール8件、レッスン24件（公開15件、下書き9件）。
- 各コースにサムネイル、5秒の無音テストMP4、英語の週間プランナーPNG。合計12ファイル。
- レッスンの添付資料リンク8件。
- 指定会員に最初の2コースの無期限の手動閲覧権限。

Hypertrophy Essentials は通常の受講者では未購入状態を確認できます。管理者はすべて閲覧できるため、未購入状態は表示されません。Coach Workshop は管理画面だけに表示されます。架空の決済やStripe価格、別の会員アカウントは作成しません。

## ファイルと動画

サムネイルはリポジトリ内の既存画像を使い、MP4と週間プランナーはローカルで生成します。生成物と固定IDの記録はGit管理対象外の `client-notes/demo-media/` に保存します。記録ファイル名は `seed-manifest-<project>-<schema>.json` で接続先ごとに分けます。動画は実際の講義ではなく、アップロードと再生確認用です。

アプリの管理画面では、Manage → 対象コース → Add a file から動画を追加します。管理者のSupabaseセッションで非公開バケットへTUS方式で直接アップロードし、完了APIがStorageのファイルサイズを照合して利用可能にします。`NEXT_PUBLIC_COURSE_SCHEMA=public` なら `course-media`、`course_staging` なら `course-staging-media` を使います。動画をアップロードした後、レッスンの動画として選択・保存してください。

アプリ上限はMP4が5GB、画像・資料が25MBですが、実際にはSupabaseプロジェクト全体のアップロード上限も適用されます。最初はこの小さなサンプルMP4で確認してください。再生時はアプリで閲覧権限を確認してから期限付きURLを発行します。自動トランスコード、複数画質への変換、DRMは実装していません。

このシードはサーバー用キーによる標準Storageアップロードを使います。管理者画面のTUSアップロード経路とは別なので、シード成功だけではブラウザからのアップロード検証済みとはなりません。

SQL Editorで `NOTIFY pgrst, 'reload schema';` を実行し、正常な読み取りに復旧しました。
テーブルの権限やRLSは変更していません。

`--content-only` で4コース・8モジュール・24レッスン・添付リンク8件・12素材を投入済み。
素材はすべて `ready`、合計7,899,245バイト。コース3件は公開、1件は下書き。
